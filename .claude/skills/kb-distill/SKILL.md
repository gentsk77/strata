# kb-distill：记来源

用户给一份材料，你记一条笔记进 `<strata>/notes/`。

## 开工前

笔记目录由 repo 根的 `strata.config.json` 配置，默认就是本 repo 的 `notes/`。先跑 `python -m kb root` 拿路径，下文 `<strata>` 指它打印的 `strata_root`；这条路径不写死进任何文件。

## 怎么做

1. 读法：[spec/note-spec.md](../../../spec/note-spec.md)（一页）与 [spec/fields.md](../../../spec/fields.md) 的字段表。
2. 整份读完，写一条 `<strata>/notes/<slug>.md`：开头两三句定位这是什么材料，正文的排法照下面「正文怎么写」，主体装原样摘录、数据、机制、用户点名在意的点，结尾记他读它时说过的话。`event_date` 是事情发生的日期（从材料里找，不是今天），`source` 一行能定位回原文，`status` 一律 `unsettled`。几份材料讲同一件事就合并成一条，正文分清出处。
3. 扫一眼已有笔记的标题，只挂真关系的链接，每条一句为什么；零链接正常。
4. `python -m kb doctor` 绿了直接提交，不问：`git -C "<strata>" add notes/ && git -C "<strata>" commit -m "distill <日期>: N notes, M links"`。**不 push**。记不成的（定位不到出处、读不了、用户判不值得）在 [spec/distill-failures.md](../../../spec/distill-failures.md) 记一行，提交在当前 repo（`distill <日期>: N failures`）。
5. 汇报：记了哪条、装了什么、挂了什么链、失败几行。

## 硬性规则

- 一份来源至多一条，永远不拆。
- 装摘录不装摘要。
- 你的推理不是笔记，提名问用户。
- 好坏对照见 [spec/note-spec.md](../../../spec/note-spec.md) 的样例。

## 正文怎么写

笔记正文是给几个月后的自己读的，不是清单。四条：

- **一条追问线，不是并列清单。** 材料里最扎人的数字或最狠的那句原话放开头，后面按「现象、表面解释、更深的追问、落点」排。重要的东西靠位置承担重量，不靠「最重要的是」这类标签。
- **每段前加一个短小标题。** 追问线保证读得下去，小标题保证查得到。标题写这一段在讲的那件事，不写「背景」「结论」这种类目。
- **具体压过概括。** 数字、原话、细节原样放进来，摘录一个字不改。
- **判断只写他的和来源的。** 你自己的推理不进正文（铁律 1）；锋利来自选材和排序，不来自你加形容词。

好坏对照：同一次实地考察，写成「周末农夫市集二十几个摊位，番茄五块一斤、鸡蛋一块五一个、蜂蜜四十一瓶」是清单；写成「卖蛋的大姐那句『便宜的都是昨天的』，整条街十几家卖同一种番茄，她家的卖得最快却从不降价；隔壁摊的价格只有一半，下午三点就收摊了。那一半的差价买走了什么」是追问线。信息量一样，后者读得完。

## 写笔记时的文字规则

一条笔记里有三处是你自己写的：开头两三句、结尾记录、给用户的汇报。写这三处时遵循下面三条：

- 不用这些词：值得注意的是、综上所述、换句话说、本质上、这意味着、赋能、总的来说。
- 不用破折号（U+2014，含全角的两个连写）。
- 用人话写：空泛指代（「某份材料」「相关内容」）换成具体名字；「内容很多」「增长很快」这类概括，能给数字就给数字。

用户的摘录和原话原样保留，不受上面约束。
