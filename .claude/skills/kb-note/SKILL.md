# kb-note：记想法

用户说了个想法，你立刻记一条。**捕捉的第一要务是不丢**：他说完你写完，不追问、不打断。

## 开工前

笔记目录由 repo 根的 `strata.config.json` 配置，默认就是本 repo 的 `notes/`。先跑 `python -m kb root` 拿路径，下文 `<strata>` 指它打印的 `strata_root`；这条路径不写死进任何文件。

## 怎么做

1. 拿到原话。调用时没带内容就问一句「记什么」，问完闭嘴。
2. 写 `<strata>/notes/<slug>.md`：标题用名字式：这个想法的名字，加一句说清（写歪了他会纠正，比追问便宜），正文用他的原话，保留锋利处。字段照 [spec/fields.md](../../../spec/fields.md)：`evidence` 多半 `inferred`、`event_date` 今天、`source: "cc-session <日期>"`、`status: unsettled`。
3. 谈到读过的东西就链到那条笔记，说得出一句为什么才挂；零链接正常。
4. `python -m kb doctor` 绿了直接提交，不问：`git -C "<strata>" add notes/<slug>.md && git -C "<strata>" commit -m "note: <标题>"`。**不 push**。然后一行汇报：记了什么、挂了几条链。

## 收工点收

他说「收工」，或一次实质对话自然收尾时：把这次他说过、值得记的想法列成清单提名（每条一句话说清是什么，加出处），他点头的逐条照上面写，没点头的一条不写。提名不出来就不硬凑。

## 硬性规则

- 只记他说的：不补论证、不补例子、不扩写。
- 三个独立想法就是三条，各自成文件。
- 不追问「你是想说 X 还是 Y」，写下你的理解让他纠正。
